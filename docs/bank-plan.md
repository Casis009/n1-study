# 문제은행 생성 계획과 진행 현황

실시간 Gemini 생성 대신 **직접 쓴 문제은행(`data/bank/<유형키>.json`)을 기본**으로 출제한다.
Gemini는 보조("AI로 새 문제")이고, 성공한 결과는 기기 안 문제은행(IndexedDB `localBank`)에만 추가된다.

## 전체 작업 순서 (2026-10-13 확정)

각 단계가 끝날 때마다 커밋·push. 커밋 단위: 문제 30~50문항(독해 5세트), 단어장 100~200개. 은행·단어장 파일이 바뀌면 sw.js VERSION을 올린다.
한도에 가까워지면 진행 중인 단위까지만 커밋·push하고 아래 "다음 시작 지점"을 고친 뒤 멈춘다.

## 기본 단어장 (data/vocab)

- 파일: `grammar.json`(g-), `kanji.json`(k-), `words.json`(w-). 형식은 src/vocab.js 상단과 tools/check-vocab.mjs 참고.
- 표제어 목록은 N1 빈출 목록을 써도 되지만, 뜻풀이·예문·비교 설명은 전부 새로 쓴다. 특정 교재의 순서·묶음을 따르지 않는다.
- 문법 `pattern`은 문제은행 `patternTags`와 같은 표기. 문자·어휘 문제의 patternTags(단어)도 kanji/words의 `word`와 같은 표기.

- 어휘(words.json)는 한자어만이 아니라 고유어(和語 동사·형용사·부사)와 가타카나어도 고르게 넣는다. 2단계 문자·어휘 문제의 정답 단어는 먼저 단어장에 넣고 같은 표기로 patternTags를 단다(2026-10-14 순서 변경: 단어장 → 문제).

## 작성 규칙

- 문법 형태·단어 같은 **항목 목록**은 N1 빈출 목록을 기준으로 삼되, **문장은 전부 새로 쓴다.** 기출·교재 문장은 쓰지 않는다.
- 빈출 항목은 여러 문제에 반복해서 나오게 하고, 문항마다 `patternTags`(예: `["〜にすぎない"]`)를 붙인다. 표기는 아래 목록과 똑같이.
- `src/prompt.js` 규칙과 같다: N1 수준, 정답은 하나만 명확하게, 해설 항목(why·kanji·grammar·compare·pattern·tip·choiceNotes) 모두 한국어, 선택지를 번호로 부르지 않기(선택지는 출제 때 섞임), 밑줄은 `__문구__`.
- 한 번에 10단위씩 쓰고, 쓸 때마다 `node --no-warnings tools/check-bank.mjs` 통과(오류 0) → 정답이 하나뿐인지·일본어가 자연스러운지 다시 읽어 검수 → 유형별로 커밋.
- **새 해설 필드 (2026-10-13 추가, 모든 문항 필수)**
  - `ex.translation = { full, ko }`: full은 정답을 넣은 완성 문장(빈칸 유형은 빈칸을 채운 문장, 文の組み立て은 올바른 순서로 완성한 문장, 독해는 질문 문장, 用法은 정답 문장), ko는 그 한국어 번역. 빈칸 유형은 full에 정답 선택지가 그대로 들어 있어야 한다.
  - `ex.choicesKo`: choices와 같은 순서로 4개 `{ reading, ko }`. reading은 20자 이하 선택지(단어·구)에 한자가 있을 때 전체 히라가나(한자가 없거나 독해처럼 문장 길이 선택지면 "", 그 속 단어는 gloss로), ko는 한국어 뜻. 출제 때 choiceNotes와 함께 섞인다.
  - 선택지에 나온 N1급 한자어도 `ex.kanji`에 넣는다.
  - 文脈規定·言い換え類義·用法의 choiceNotes는 자동 분류 문장을 쓰지 않는다. 오답마다 "이 단어는 어떤 문맥에 쓰는지"(대표 연어·예)를 직접 쓴다. 이 유형은 오답 이유가 핵심이다.
  - `gloss = [{ w, r, m }]`(문항): stem과 choices에 나온 N2~N1급 단어, 문장당 3~8개. w는 문장에 나온 그대로의 표기(활용형 그대로)이고 ★·밑줄(`__`) 경계를 넘지 않는다. 기초 단어는 넣지 않는다.
  - 지문형 단위: `passageKo`(지문 전체 한국어 번역, 단락 줄바꿈 유지)와 `passageGloss`(지문 단어, 단락마다 3~8개).
  - 기본 단어장 항목: `gloss`(예문 단어, 3~8개).
  - 화면: 단어 탭(점선 밑줄 → 팝업)과 지문 해석은 **정답 확인 뒤에만** 보인다(풀 때 힌트가 되지 않게). 오답노트·단어장에서는 항상.
  - 검사: check-bank / check-vocab의 `NEW_FIELDS_STRICT`. 보완(5a) 완료로 2026-10-14부터 true(누락도 오류). 형식이 틀린 값(gloss w가 문장에 없음 등)은 지금도 오류.
- 내 문제(교재 문제 직접 입력)는 기기 IndexedDB에만 저장한다. `data/`에는 절대 넣지 않는다.

## 출제·복습 규칙 (src/bank.js)

- 안 푼 단위(무작위) → 복습 시각이 지난 단위(오래된 순). 둘 다 없으면 "다 풀었어요" + [그래도 풀기].
- 틀리거나 "찍어서 맞힘"으로 저장하면 **1일 → 3일 → 7일 → 14일** 뒤 다시 출제, 14일 복습까지 맞히면 졸업. 처음에 바로 맞힌 단위는 복습 없음.
- 지문형은 세트 안에서 하나라도 틀리면 세트 전체가 복습 대상. 출제 때마다 선택지(와 문항형의 문항 순서)를 섞는다.

## N1 빈출 문법 항목 (patternTags 표기 기준)

항목 이름만 목록으로 쓴다. 정답 패턴으로 나온 문항 수는 `tools/check-bank.mjs` 출력의 "패턴" 줄에서 확인한다.

文章の文法 patternTags: 문법 형식은 `〜` 패턴(단어장 문법과 같은 표기), 그 밖에는 `接続表現`, `指示語`, `文末表現`, `受身・使役`, `文の形`.

독해 patternTags는 질문 유형으로 붙인다: `筆者の考え`, `下線部の理由`, `下線部の意味`, `内容一致`, `AとBの共通点`, `AとBの相違点`, `情報検索・条件`.

1단계 文法形式の判断 30문항: 26개 패턴, 그중 〜を余儀なくされる·〜にかたくない·〜といえども·〜はおろか는 2문항씩(문장은 서로 다름).
